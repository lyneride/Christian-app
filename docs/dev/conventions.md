## 1. Next.js 16 routing and file conventions

### Files that matter

| File | Role |
| --- | --- |
| `src/app/layout.tsx` | Root layout, must render `<html>` and `<body>`. |
| `src/app/**/page.tsx` | Makes a segment public. Leaf of the tree. |
| `loading.tsx` | Suspense fallback for `page.tsx` and below (not for the sibling `layout.tsx`). |
| `error.tsx` / `global-error.tsx` | Error boundaries, must be `'use client'`. |
| `not-found.tsx` | Rendered by `notFound()`; the root one also catches unmatched URLs. |
| `route.ts` | Route Handler. Cannot sit next to a `page.tsx` in the same segment. |
| `default.tsx` | **Required for every parallel-route slot (`@slot`) in 16, build fails without it.** |
| `src/proxy.ts` | Formerly `middleware.ts`. Lives next to `app/`. |
| `(group)/`, `_private/`, `[slug]`, `[...all]`, `[[...opt]]`, `@slot`, `(.)intercept` | Route groups, private folders, dynamic/catch-all, slots, intercepting routes. |

Turbopack is the default for `next dev` and `next build` (no `--turbopack` flag). `next dev` writes to `.next/dev`, so dev and build can run concurrently. `next lint` is gone; run `eslint` (already wired in `package.json`). `next-env.d.ts` is generated and gitignored.

### `params` and `searchParams` are Promises (sync access removed in 16)

```tsx
// src/app/blog/[slug]/page.tsx
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params
  const { q } = await props.searchParams   // Promise<{ [key: string]: string | string[] | undefined }>
  return <h1>{slug}</h1>
}
```

- `PageProps<'/route'>`, `LayoutProps<'/route'>` and `RouteContext<'/route'>` are **global** helpers, no import. They are generated by `next dev`, `next build` or `next typegen` (run `next typegen && tsc --noEmit` in CI). Static routes resolve `params` to `{}`.
- The scaffolded `layout.tsx` already uses `LayoutProps<"/">`; a layout with a slot `app/dashboard/@analytics` gets a typed `props.analytics`.
- Client Components cannot be `async`; unwrap with `use(params)` from `react`.
- Also Promises now: `cookies()`, `headers()`, `draftMode()`, and the `params`/`id` of `opengraph-image`, `icon`, `sitemap`.

### Route Handlers

```ts
// src/app/api/users/[id]/route.ts
import type { NextRequest } from 'next/server'

export async function GET(req: NextRequest, ctx: RouteContext<'/api/users/[id]'>) {
  const { id } = await ctx.params
  const q = req.nextUrl.searchParams.get('q')
  return Response.json({ id, q })
}
export async function POST(req: Request) {
  const body = await req.json()           // or await req.formData()
  return Response.json(body, { status: 201 })
}
```

Supported exports: `GET HEAD POST PUT PATCH DELETE OPTIONS`. Handlers are **not cached by default** (since 15). Without Cache Components, opt in with `export const dynamic = 'force-static'` / `export const revalidate = 60`.

### `proxy.ts` (was `middleware.ts`)

```ts
// src/proxy.ts
import { NextResponse, type NextRequest } from 'next/server'

export function proxy(request: NextRequest) {           // named `proxy` or default export
  const session = request.cookies.get('session')?.value
  if (!session && request.nextUrl.pathname.startsWith('/dashboard')) {
    return NextResponse.redirect(new URL('/login', request.url))
  }
  return NextResponse.next()
}

export const config = {
  matcher: ['/((?!api|_next/static|_next/image|favicon.ico|sitemap.xml|robots.txt).*)'],
}
```

- Runtime is **Node.js only**; `runtime` config is not allowed in proxy. `NextProxy` type exists in `next/server`.
- Order: `headers` config, `redirects` config, proxy, rewrites, filesystem routes.
- Server Actions are POSTs to the page's own route, so a matcher that excludes a path also skips its actions. Never rely on proxy alone for auth.
- Codemod if migrating: `npx @next/codemod@canary middleware-to-proxy .`. `skipMiddlewareUrlNormalize` is now `skipProxyUrlNormalize`.

### Navigation

```tsx
import Link from 'next/link'
import Form from 'next/form'
<Link href="/blog" prefetch={false}>Blog</Link>      // prefetch={null|false|true}
<Form action="/search"><input name="q" /><button>Go</button></Form>  // GET + client nav + prefetch
```

`useLinkStatus()` from `next/link` gives `{ pending }` for slow links. `redirect()` / `permanentRedirect()` from `next/navigation` work in Server Components, Server Functions, Route Handlers (they **throw**, call outside `try`). In Client event handlers use `useRouter().push()`.

### `next.config.ts` options worth knowing

```ts
import type { NextConfig } from 'next'
const nextConfig: NextConfig = {
  typedRoutes: true,            // typed <Link href> (literal strings; cast with `as Route` otherwise)
  reactCompiler: true,          // stable, OFF by default; needs `npm i -D babel-plugin-react-compiler`
  // cacheComponents: true,     // OFF by default, see section 3
  serverExternalPackages: [],   // @prisma/client, prisma, better-sqlite3 are already in Next's built-in list
  turbopack: {},                // top-level now (was experimental.turbopack)
  images: { remotePatterns: [{ protocol: 'https', hostname: 'example.com' }] }, // images.domains is deprecated
}
export default nextConfig
```

Image defaults changed in 16: `minimumCacheTTL` 4h, `qualities` `[75]`, `imageSizes` without 16, max 3 redirects, local images with query strings need `images.localPatterns[].search`.

## 2. Server / Client Components and Server Actions

- Everything in `app/` is a Server Component unless the file starts with `'use client'`. Put the directive on leaf interactive components, not on layouts.
- Mark server-only modules with `import 'server-only'` (Next provides the types; the npm package is optional). Only `NEXT_PUBLIC_*` env vars reach the client.
- Pass Server Components into Client Components as `children`; context providers are Client Components that wrap `{children}`.
- Dedupe DB reads per request with `React.cache` (fetch is memoized automatically):

```ts
import { cache } from 'react'
export const getUser = cache(async (id: string) => prisma.user.findUnique({ where: { id } }))
```

### Server Actions (React Server Functions)

```ts
// src/app/posts/actions.ts
'use server'
import * as z from 'zod'
import { revalidatePath, updateTag, refresh } from 'next/cache'
import { redirect } from 'next/navigation'
import { verifySession } from '@/lib/dal'
import { prisma } from '@/lib/db'

type FormState = { errors?: Record<string, string[] | undefined> } | undefined

export async function createPost(prevState: FormState, formData: FormData): Promise<FormState> {
  const session = await verifySession()           // ALWAYS re-check auth inside the action
  const parsed = PostSchema.safeParse({ title: formData.get('title') })
  if (!parsed.success) return { errors: z.flattenError(parsed.error).fieldErrors }  // return, don't throw
  const post = await prisma.post.create({ data: { ...parsed.data, authorId: session.userId } })
  revalidatePath('/posts')                        // or updateTag('posts') with Cache Components
  redirect(`/posts/${post.id}`)                   // throws; must come last and outside try/catch
}
```

```tsx
// src/app/posts/new-post-form.tsx
'use client'
import { useActionState } from 'react'
import { useFormStatus } from 'react-dom'
import { createPost } from './actions'

export function NewPostForm() {
  const [state, formAction, pending] = useActionState(createPost, undefined)
  return (
    <form action={formAction}>
      <input name="title" required />
      {state?.errors?.title && <p aria-live="polite">{state.errors.title[0]}</p>}
      <button disabled={pending}>Create</button>
    </form>
  )
}
```

Conventions:

- With `useActionState` the action signature becomes `(prevState, formData)`. Model expected errors as **return values**; only bugs should throw (they hit `error.tsx`).
- Extra args: `updateUser.bind(null, userId)`; hidden inputs are visible in HTML.
- Zod 4 is installed: messages use `{ error: '...' }` (not `message`/`invalid_type_error`), `z.email()` is top-level, and `.flatten()` is deprecated in favour of `z.flattenError(err)` / `z.treeifyError(err)`.
- Cache updates from `next/cache`: `revalidatePath(path, 'page' | 'layout'?)`, `revalidateTag(tag, 'max')` (**second argument is now required**, stale-while-revalidate), `updateTag(tag)` (Server Actions only, read-your-own-writes), `refresh()` (Server Actions only, re-render current route without invalidating).
- Cookies: `(await cookies()).set/delete` only in Server Functions and Route Handlers; a cookie change re-renders the current page in the same round trip.
- Security: actions are public POST endpoints. Validate input, authorize ownership (IDOR), return only what the UI needs, prefer a server-only DAL with thin `'use server'` wrappers. `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` must be stable across instances when self-hosting several. Body limit 1 MB via `experimental.serverActions.bodySizeLimit`.
- The client dispatches actions **sequentially**; do not `Promise.all` actions.
- `useOptimistic` for optimistic UI; `useEffect` + `startTransition` to fire an action on mount.

## 3. Caching model in 16

**`cacheComponents` is OFF by default.** The scaffolded `next.config.ts` does not set it, so this app runs the "previous model" until someone opts in. The two models are different enough that you must know which one you are in.

### Previous model (current default here)

- `fetch` is **not** cached unless `{ cache: 'force-cache' }` or `{ next: { revalidate, tags } }`.
- A route is dynamic when it reads `cookies()`, `headers()`, `searchParams`, `connection()`, or uses `export const dynamic = 'force-dynamic'`. Otherwise it is **prerendered at build time, including Prisma queries** (stale data gotcha for public pages).
- Segment configs: `dynamic`, `revalidate`, `fetchCache`, `dynamicParams`, `runtime` (`'edge'` deprecated).
- Non-fetch caching: `unstable_cache(fn, keyParts, { tags, revalidate })` (docs: "replaced by `use cache` in 16").
- `loading.tsx` works for pages, but an `await cookies()` at the top of a **layout** blocks navigation (layout is above the Suspense boundary).

```ts
// public page that must always hit the DB
export const dynamic = 'force-dynamic'
```

### Cache Components model (`cacheComponents: true`)

- Enables `'use cache'`, `cacheLife`, `cacheTag`, `'use cache: private'`, `'use cache: remote'`, PPR by default, React `<Activity>` state preservation on navigation, `instant` validation.
- Removes `dynamic`, `revalidate`, `fetchCache`, `dynamicParams`, `experimental_ppr`, `experimental.useCache/dynamicIO`. Node.js runtime only.
- Rules: runtime APIs (`cookies()`, `headers()`, `params`, `searchParams`) and uncached async work must sit inside `<Suspense>`; `'use cache'` functions cannot read `cookies()`/`headers()` (pass values as args); `Math.random()`, `Date.now()`, `crypto.randomUUID()` and **synchronous `better-sqlite3` reads** are captured at build unless preceded by `await io()` (16.3, `next/cache`) or `await connection()` (`next/server`).

```ts
import { cacheLife, cacheTag } from 'next/cache'

export async function getEvents() {
  'use cache'
  cacheLife('hours')           // seconds | minutes | hours | days | weeks | max | default, or an object
  cacheTag('events')
  return prisma.event.findMany()
}

export async function getCurrentUser() {
  'use cache: private'         // may read cookies(); cached in the browser only
  const { userId } = await getSession()
  return userId ? findUserById(userId) : null
}
```

```tsx
export default function Page() {
  return (
    <>
      <Hero />                                             {/* static shell */}
      <Suspense fallback={<Skeleton />}><Dashboard /></Suspense>  {/* reads cookies, streams */}
    </>
  )
}
```

Opt a segment out of validation while migrating: `export const instant = false` (or `npx @next/codemod@canary cache-components-instant-false ./src/app`). Cache keys and tags are stored in **plain text**: never put secrets or emails in args/tags.

### Recommendation for this (mostly dynamic, authenticated, SQLite) app

1. Start with `cacheComponents` **off**. Every authenticated page reads the session cookie through the DAL, so it is dynamic anyway; use `React.cache` for per-request dedupe and `revalidatePath`/`refresh()` after mutations. Add `export const dynamic = 'force-dynamic'` to public DB-backed pages that must be live, or `export const revalidate = 60` where ISR is fine.
2. Do not use `unstable_cache` for new code; it is a dead end. If you need cross-request caching, that is the signal to flip `cacheComponents: true`.
3. When you flip it: run the `instant-false` codemod, replace segment configs, wrap session reads in `<Suspense>`, move `getCurrentUser` to `'use cache: private'`, tag per-user data with a per-user tag such as `cacheTag('notes:' + userId)` and invalidate it with `updateTag` in actions. See `02-guides/authentication-with-cache-components.md`.

## 4. Auth pattern: cookie session + Data Access Layer

Stateless JWT session (jose) in an `HttpOnly` cookie, verified in a server-only DAL. Proxy only does optimistic redirects.

```ts
// src/lib/session.ts
import 'server-only'
import { SignJWT, jwtVerify } from 'jose'
import { cookies } from 'next/headers'

const key = new TextEncoder().encode(process.env.SESSION_SECRET)   // openssl rand -base64 32
type SessionPayload = { userId: string; expiresAt: Date }

export async function encrypt(payload: SessionPayload) {
  return new SignJWT(payload).setProtectedHeader({ alg: 'HS256' }).setIssuedAt().setExpirationTime('7d').sign(key)
}
export async function decrypt(session: string | undefined = '') {
  try { return (await jwtVerify(session, key, { algorithms: ['HS256'] })).payload as SessionPayload }
  catch { return null }
}
export async function createSession(userId: string) {
  const expiresAt = new Date(Date.now() + 7 * 24 * 60 * 60 * 1000)
  ;(await cookies()).set('session', await encrypt({ userId, expiresAt }), {
    httpOnly: true, secure: true, sameSite: 'lax', path: '/', expires: expiresAt,
  })
}
export async function deleteSession() { (await cookies()).delete('session') }
```

```ts
// src/lib/dal.ts
import 'server-only'
import { cache } from 'react'
import { cookies } from 'next/headers'
import { redirect } from 'next/navigation'
import { decrypt } from '@/lib/session'
import { prisma } from '@/lib/db'

export const verifySession = cache(async () => {
  const session = await decrypt((await cookies()).get('session')?.value)
  if (!session?.userId) redirect('/login')
  return { isAuth: true as const, userId: session.userId }
})

export const getUser = cache(async () => {
  const { userId } = await verifySession()
  return prisma.user.findUnique({ where: { id: userId }, select: { id: true, name: true, email: true } }) // DTO, never the whole row
})
```

```ts
// src/app/(auth)/actions.ts
'use server'
import * as z from 'zod'
import bcrypt from 'bcryptjs'
const SignupSchema = z.object({
  name: z.string().min(2, { error: 'Name must be at least 2 characters long.' }).trim(),
  email: z.email({ error: 'Please enter a valid email.' }).trim(),
  password: z.string().min(8, { error: 'Be at least 8 characters long' }),
})
export async function signup(state: FormState, formData: FormData) {
  const parsed = SignupSchema.safeParse(Object.fromEntries(formData))
  if (!parsed.success) return { errors: z.flattenError(parsed.error).fieldErrors }
  const user = await prisma.user.create({ data: { ...parsed.data, password: await bcrypt.hash(parsed.data.password, 10) } })
  await createSession(user.id)
  redirect('/dashboard')
}
```

Rules from the docs:

- Check auth **in pages, leaf components, actions and route handlers**, not in layouts (layouts do not re-render on navigation and do not stop child segments from rendering). `return null` in a layout is not a security boundary.
- Keep the session read out of the layout's top level; put the user menu in a nested component inside `<Suspense>`.
- Client Components cannot import the DAL. Read the user in a Server Component and pass a narrow object (or a promise consumed with `use()` via a context provider).
- Proxy: read the cookie only (`request.cookies.get('session')` or `await cookies()`), no DB calls, since it runs on every request including prefetches.
- Secrets live in env vars and are read only inside the DAL. Optional `experimental.taint: true` + `experimental_taintUniqueValue` to stop sensitive values reaching the client.

## 5. Metadata, errors, not-found, loading

```tsx
// static
import type { Metadata, ResolvingMetadata } from 'next'
export const metadata: Metadata = { title: { template: '%s | Christian App', default: 'Christian App' } }

// dynamic (Server Components only; cannot export both metadata and generateMetadata)
export async function generateMetadata({ params }: PageProps<'/events/[id]'>, parent: ResolvingMetadata): Promise<Metadata> {
  const event = await getEvent((await params).id)        // wrap getEvent in React.cache to share with the page
  return { title: event.title, openGraph: { images: [...((await parent).openGraph?.images ?? [])] } }
}
```

- Metadata streams after the UI for browsers; HTML-limited bots get it in `<head>`. Under Cache Components, `generateMetadata` that reads runtime data needs the page to have a dynamic part too, or use `'use cache'` inside it.
- File conventions: `app/favicon.ico`, `app/opengraph-image.tsx` (`ImageResponse` from `next/og`, `export const size`, `contentType`), `app/sitemap.ts`, `app/robots.ts`, `app/manifest.ts` (`MetadataRoute.Manifest`, PWA). Do not hand-write `<head>` tags in the root layout.

```tsx
// src/app/dashboard/error.tsx
'use client'
export default function Error({ error, retry }: { error: Error & { digest?: string }; retry: () => void }) {
  return <button onClick={() => retry()}>Try again ({error.digest})</button>  // `retry` stable in 16.3; `reset` still exists
}
```

- `global-error.tsx` replaces the root layout, must render `<html>`/`<body>`, gets no global CSS. `catchError(Fallback)` from `next/error` builds component-level boundaries.
- Production server errors are redacted: the client only sees `error.digest`; match it in server logs.
- `notFound()` from `next/navigation` renders the nearest `not-found.tsx`. Streamed 404s return HTTP 200 plus `<meta name="robots" content="noindex">`; call `notFound()` before any `await` that suspends if you need a real 404 status.
- `loading.tsx` is a Suspense boundary around `page.tsx`; prefer explicit `<Suspense>` near the slow read. Bots get the fully rendered page.
- `after(() => ...)` from `next/server` runs work after the response (logging, email). In Server Components read `cookies()` **before** calling `after`, not inside the callback.

## 6. Prisma 7 with the better-sqlite3 adapter

What changed from Prisma 5/6: no Rust query engine, a **driver adapter is required**, the datasource `url` moved out of `schema.prisma` into a TypeScript config file, `.env` is **not** auto-loaded, the default generator is `prisma-client` with a mandatory `output`, `migrate dev`/`db push` no longer run `generate` or seed, `$use` middleware and `Prisma.validator` are gone.

### Config file

The scaffold created `prisma7.config.ts`. Prisma 7.10's loader looks for `prisma7.config.{js,ts,mjs,cjs,mts,cts}` and `.config/prisma7.*` first, then the legacy `prisma.config.*` names, so the name is fine. Keep it (it lets a future Prisma 8 `prisma.config.ts` coexist) or rename to `prisma.config.ts`; both are auto-discovered. Note: `dotenv` is only installed transitively today; add it explicitly.

```bash
npm i -D dotenv tsx
```

```ts
// prisma7.config.ts
import 'dotenv/config'                       // must be the first import; Prisma does not load .env itself
import { defineConfig, env } from 'prisma/config'

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: {
    path: 'prisma/migrations',
    seed: 'tsx prisma/seed.ts',              // run with `prisma db seed`, never automatically
  },
  datasource: {
    url: env('DATABASE_URL'),                // throws if missing; `process.env['DATABASE_URL']` also accepted
    // shadowDatabaseUrl: env('SHADOW_DATABASE_URL'),  // not needed for SQLite
  },
})
```

`.env`: `DATABASE_URL="file:./dev.db"`. The adapter strips `file:` and hands the path to `better-sqlite3`, i.e. relative to `process.cwd()`. The CLI resolves relative paths itself and the official skill warns the two can differ, so always run `prisma` and `next` from the repo root and check where `dev.db` is created on the first `migrate dev`. Add `*.db` to `.gitignore`.

### Schema

```prisma
// prisma/schema.prisma
generator client {
  provider = "prisma-client"          // new ESM-ready generator; "prisma-client-js" is legacy
  output   = "../src/generated/prisma" // required; gitignored by the scaffold
  // defaults derived from tsconfig (module: esnext, moduleResolution: bundler):
  // runtime = "nodejs", moduleFormat = "esm", generatedFileExtension = "ts", importFileExtension = ""
  // previewFeatures = ["partialIndexes"]
}

datasource db {
  provider = "sqlite"                 // no url here anymore (deprecated); it lives in the config file
}

model User {
  id        String   @id @default(cuid())
  email     String   @unique
  name      String
  password  String
  createdAt DateTime @default(now())
  posts     Post[]
}
```

SQLite limits: no scalar lists (`String[]`), enums are not enforced by the DB, writes lock the file.

### Client singleton

```ts
// src/lib/db.ts
import 'server-only'
import { PrismaClient } from '@/generated/prisma/client'         // NOT from '@prisma/client'
import { PrismaBetterSqlite3 } from '@prisma/adapter-better-sqlite3'

const createClient = () =>
  new PrismaClient({
    adapter: new PrismaBetterSqlite3({ url: process.env.DATABASE_URL ?? 'file:./dev.db' }),
    log: process.env.NODE_ENV === 'development' ? ['query', 'warn', 'error'] : ['error'],
  })

const globalForPrisma = globalThis as unknown as { prisma?: ReturnType<typeof createClient> }
export const prisma = globalForPrisma.prisma ?? createClient()
if (process.env.NODE_ENV !== 'production') globalForPrisma.prisma = prisma   // survive HMR in dev
```

`PrismaClientOptions` is `{ adapter } | { accelerateUrl }`: the constructor **requires** one of them. `PrismaBetterSqlite3` accepts `better-sqlite3` `Options` plus `url` (`':memory:'` allowed) and a second arg `{ shadowDatabaseUrl?, timestampFormat?: 'iso8601' | 'unixepoch-ms' }`.

Other imports from the generated folder: `@/generated/prisma/client` (`PrismaClient`, `Prisma` namespace, server only), `@/generated/prisma/browser` (browser-safe types), `@/generated/prisma/enums`, `@/generated/prisma/models` and `models/User`. Use these in Client Components, never `client`. The generated code imports its runtime from `@prisma/client/runtime`, so keep `@prisma/client` installed.

Typed fragments: `const userSelect = { id: true, email: true } satisfies Prisma.UserSelect` (`Prisma.validator` no longer exists). Middleware: `new PrismaClient({ adapter }).$extends({ query: { $allModels: { async $allOperations({ query, args }) { return query(args) } } } })`. Use `findUniqueOrThrow` instead of `rejectOnNotFound`.

### Scripts and workflow

```json
{
  "scripts": {
    "postinstall": "prisma generate",
    "db:generate": "prisma generate",
    "db:migrate": "prisma migrate dev",
    "db:push": "prisma db push",
    "db:seed": "prisma db seed",
    "db:studio": "prisma studio",
    "db:deploy": "prisma migrate deploy"
  }
}
```

- Dev: edit schema, then `npx prisma migrate dev --name add_posts` **and** `npx prisma generate` (generate is no longer automatic; `--skip-generate`/`--skip-seed` flags were removed). Prototyping: `npx prisma db push` then `generate`.
- `prisma db seed` runs `migrations.seed` from the config; seeds should be idempotent (`upsert`). `prisma/seed.ts` builds its own client exactly like `lib/db.ts` (without `server-only`).
- Prod: `prisma migrate deploy`. Override the URL ad hoc with `--url` (`prisma db push --url file:./test.db`), or `--config path`.
- Destructive commands (`migrate reset`, `db push --force-reset|--accept-data-loss`) are blocked when an AI agent is detected until the user consents (`PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION`).
- `migrate diff` flags renamed: `--from-config-datasource` / `--to-config-datasource`.

### Next.js / Turbopack notes

- `@prisma/client`, `prisma` and `better-sqlite3` are in Next's built-in `serverExternalPackages` list, so the native module is required at runtime, not bundled. The generated `src/generated/prisma/*.ts` files are ordinary app code and bundle fine. Only add `serverExternalPackages: ['@prisma/adapter-better-sqlite3']` if you hit a bundling error.
- Prisma queries are async, so under Cache Components they count as "uncached data" (wrap in `<Suspense>` or `'use cache'`); the raw sync `better-sqlite3` API is the one that silently runs at build time.
- The scaffold lists `prisma` under `dependencies` rather than `devDependencies`; keep it there if your production install runs `postinstall: prisma generate`, since the CLI must be present at install time.

## 7. Tailwind CSS v4 tokens and dark mode

No `tailwind.config.js`, no `content` array, no `@tailwind base/components/utilities`. PostCSS plugin is `@tailwindcss/postcss` (already in `postcss.config.mjs`). Sources are auto-detected (gitignored paths such as `src/generated/prisma` are skipped); add `@source "../node_modules/some-lib";` only for external packages.

```css
/* src/app/globals.css */
@import "tailwindcss";

@custom-variant dark (&:where(.dark, .dark *));   /* class-based dark mode; default `dark:` is prefers-color-scheme */

:root {
  --background: oklch(100% 0 0);
  --foreground: oklch(14.5% 0 0);
  --primary: oklch(55% 0.2 260);
}
.dark {
  --background: oklch(14.5% 0 0);
  --foreground: oklch(98.5% 0 0);
}

@theme inline {                                   /* `inline`: utilities use the var's current value, so .dark swaps work */
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --font-sans: var(--font-geist-sans);             /* set by next/font in layout.tsx */
  --font-mono: var(--font-geist-mono);
}

@theme {                                          /* plain tokens become CSS vars + utilities */
  --radius-card: 1rem;                            /* rounded-card */
  --breakpoint-3xl: 120rem;                       /* 3xl: */
  --animate-fade: fade 200ms ease-out;            /* animate-fade */
  @keyframes fade { from { opacity: 0 } to { opacity: 1 } }
}

@utility scrollbar-none { scrollbar-width: none; }  /* custom utility, works with variants */
```

- Namespaces shipped in `theme.css`: `--color-*`, `--font-*`, `--text-*`, `--spacing`, `--breakpoint-*`, `--container-*`, `--radius-*`, `--shadow-*`, `--inset-shadow-*`, `--drop-shadow-*`, `--blur-*`, `--tracking-*`, `--leading-*`, `--animate-*`, `--ease-*`, `--perspective-*`, `--aspect-*`. `--color-primary` gives `bg-primary`, `text-primary`, `border-primary`, etc.
- Default colors are `oklch`. Clear a namespace with `--color-*: initial;` before redefining.
- Dark mode: toggle the `dark` class on `<html>` with an inline `<script>` in `<head>` before paint (reading a cookie on the server makes the whole tree request-bound). `global-error` and the built-in 404 do not get your theme class.
- Other directives: `@variant`, `@apply`, `@reference "./globals.css"` (for CSS modules), `@plugin`, `@config` (legacy JS config only if truly needed).

## 9. Gotchas

1. `params`, `searchParams`, `cookies()`, `headers()`, `draftMode()` are Promises; sync access that still worked in 15 is gone.
2. `middleware.ts` is `proxy.ts` (`export function proxy`), Node runtime only, and it does not guard Server Actions reliably.
3. Parallel-route slots without `default.tsx` fail the build.
4. `revalidateTag('x')` with one argument is deprecated (TS error); use `revalidateTag('x', 'max')` or `updateTag('x')` in actions.
5. `cacheComponents` is opt-in; enabling it removes `dynamic`/`revalidate`/`fetchCache` and turns un-suspended `cookies()` reads into build-time insights/errors. `'use cache'` functions cannot read cookies.
6. Without Cache Components, a page with only DB queries and no request APIs is prerendered at build (stale data). Use `force-dynamic`, `revalidate`, or read request data.
7. `redirect()`/`notFound()` throw; never wrap them in `try/catch`, and call `revalidatePath` before `redirect`.
8. `error.tsx` must be a Client Component and receives `retry` (and legacy `reset`); server error messages are redacted in production (use `digest`).
9. Streamed 404s and redirects return HTTP 200; check existence before the first suspending `await` or in proxy if you need the real status.
10. `next lint` is removed; `next build` does not lint. `next dev` outputs to `.next/dev`. Custom `webpack` config fails `next build` unless `--webpack`.
11. Prisma: `.env` is not loaded by the CLI (`import 'dotenv/config'` first in the config); `dotenv` is not yet a direct dependency.
12. Prisma: `prisma migrate dev` / `db push` no longer run `prisma generate`; seeds only run via `prisma db seed`; the generated client is gitignored, so wire `postinstall: prisma generate`.
13. Prisma: import `PrismaClient` from `@/generated/prisma/client`, never `@prisma/client`; constructor without `adapter` is a type error; `Prisma.validator` and `$use` are gone.
14. Prisma: `prisma7.config.ts` is a valid auto-discovered name in 7.x; `file:` paths resolve against cwd in the adapter, so run everything from the repo root.
15. Zod 4: `{ error }` instead of `{ message }`, `z.email()` top-level, `.flatten()` deprecated (`z.flattenError`).
16. Tailwind 4: `@import "tailwindcss"` only, `@theme`/`@theme inline` for tokens, `dark:` follows `prefers-color-scheme` unless you declare `@custom-variant dark (...)`.
17. Vitest cannot render async Server Components; test them with Playwright.
18. Images: `images.domains` deprecated (use `remotePatterns`); local images with `?query` need `localPatterns.search`; `next/legacy/image` deprecated.
19. Node 20.9+ and TypeScript 5.1+ are required by Next 16; Prisma 7 needs Node 20.19+ and TS 5.4+. This box runs Node 22.22.
20. `after()` cannot call `cookies()`/`headers()` inside its callback in Server Components; read them first and close over the values.
